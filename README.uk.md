# KSTAR · сторінка статусів

[English](README.md) · **Українська**

Компактна сторінка статусів гібридних інверторів KSTAR, що працює поверх порталу [KSTAR Sync](https://sync.ksdatacloud.com/). Її зробив власник системи KSTAR в Україні, де планові й аварійні відключення трапляються майже щодня. Сторінка відповідає на питання, які офіційний веб- і Android-застосунок лишають відкритими: *чи є зараз світло, з якого моменту, на скільки вистачить батареї і як часто це повторюється?*

Перевірено на **E5KS-D22** з двома модулями **BluE-Pack** (Wi-Fi даталогер, прошивка ARM V1.8.12 / DSP V2.2.04). Сторінка розрахована на будь-який акаунт KSTAR Sync з житловою гібридною системою: ємність батареї береться з BMS, час показується в часовому поясі станції, для трьох фаз значення підсумовуються, а за кількох станцій з'являється список для вибору. На трифазних моделях (E…KT) і з батареями інших виробників на реальному обладнанні ще не перевірялось; відгуки вітаються. Інтерфейс двомовний: перемикач UA/EN у шапці, за замовчуванням мова браузера.

**Встановлення:** https://vlgook.github.io/kstar-status/

## Як це працює

API порталу не приймає запити з інших сайтів (немає заголовків CORS), тому окремим сайтом сторінка працювати не може. Її запускає закладка з відкритої вкладки порталу:

1. закладка завантажує `dash.html` з GitHub Pages;
2. відкриває нову вкладку з тим самим origin, що й портал;
3. сторінка читає токен сесії порталу з `localStorage` і щохвилини опитує API.

Пароль і токен не залишають браузер, запити йдуть лише на sync.ksdatacloud.com. Якщо натиснути закладку на сторінці станції (`/station/<id>/…`), відкриється саме вона, інакше перша станція в акаунті.

## Що показує

| Блок | Вміст |
|---|---|
| Смуга вгорі | Є чи немає мережі і точний час останньої зміни за журналом тривог: `saveTime` активної W00/W02/W03, `removeTime` останньої знятої |
| Батарея | SoC, запас роботи до межі розряду без мережі, прочитаної з інвертора (`offgriddod`), поточне навантаження |
| Статуси | Система, інвертор, режим роботи, зв'язок (за свіжістю даних), прошивка з перевіркою оновлень |
| Мережа і вихід інвертора | Напруга й частота мережі (мін–макс за добу), вихід інвертора, резервна лінія, межа вихідного струму, власні потреби системи |
| Аварії | Активні аварії з кодами |
| Батарейні модулі | SoC, напруга, струм кожного модуля; BMS: SOH, цикли, ємність, розкид напруги комірок, температури комірок і MOS, балансування |
| Енергія | Сьогодні / місяць / рік / всього: імпорт, будинок, заряд і розряд батареї, експорт, баланс власних потреб |
| Ресурс батареї | Лічильник циклів BMS відносно умовного ресурсу, заряджено й розряджено за весь час |
| Статистика відключень | 7/14/28 днів: кількість, сумарне і найдовше відключення, короткі провали, 24-годинна смуга по кожному дню, частка днів без світла по годинах |
| Графік за добу | SoC, навантаження й імпорт з точними інтервалами відключень і позначками коротких провалів; напруга мережі й інвертора з межами ±10%; перемикання днів |

Додатково: **живий режим** (Quick Update порталу, дані кожні ~10 с, сам вимикається через 10 хв) і **сповіщення в браузері зі звуком** про зникнення й повернення мережі, SoC 30/15/95% і втрату зв'язку, поки вкладка відкрита.

## Ідеї для KSTAR Sync

Що виявилось корисним у щоденному житті і могло б з'явитися в офіційних застосунках:

1. **Push-сповіщення** про зникнення й повернення мережі, низький SoC і втрату зв'язку даталогера. Саме з цього проєкт і почався.
2. **«Мережа є/немає з …»** на головному екрані. Дані вже є в журналі тривог (`saveTime` / `removeTime`), їх просто не показують.
3. **Статистика відключень**: смуга по днях і гістограма за годинами. У регіонах з частими відключеннями власник хоче знати це насамперед.
4. **Прогноз запасу** при поточному навантаженні з урахуванням реального off-grid DOD.
5. **Короткі провали мережі** (40–60 с) видно лише в журналі тривог, на 5-хвилинних графіках вони зникають повністю.
6. **Власні потреби системи** (DC батареї мінус AC інвертора під час відключень): на цьому інверторі стабільно ~60–65 Вт, близько 1,5 кВт·год на добу.

Спостереження під час роботи з API, які можуть знадобитися команді порталу:

- `overview/version` і `overview/realdata/v2` повертають HTTP 500 без `stime` (поточний час станції) і заголовка `Accept-Language`.
- `communStatus` у списку станцій може показувати 0, хоча свіжі дані продовжують надходити.
- API віддалених налаштувань повертає підписи `ongriddod` / `offgriddod` і Demand Control китайською навіть з `Accept-Language: en` (веб-інтерфейс перекладає їх сам), а поточні значення порожні, доки не натиснути Read.
- Оновлення прошивки показують лише номери версій; опис змін допоміг би власникам і монтажникам вирішувати, коли оновлюватись.

## Ендпоінти API

| Дані | Запит |
|---|---|
| Станції | `POST /api/web/station/list/page/v2` `{current, size}` |
| Інформація про станцію, часовий пояс | `GET /api/web/station/manager/getinfo?stationId=…` |
| SoC, потоки потужності, режим | `GET /api/residential/device/detail/logic?collectId=…&refreshFlag=false` |
| Час останніх даних | `GET /api/residential/device/detail/navigation/data?collectId=…` |
| Статуси системи, прошивка, межі | `GET /api/residential/device/detail/overview/version?deviceId=…&stime=…` |
| Модулі, лічильники енергії | `GET /api/residential/device/detail/overview/realdata/v2?deviceId=…&stime=…` |
| 5-хвилинна історія за добу (U, f, P мережі й інвертора) | `GET /api/residential/history/data/kse/list?deviceId=…&stime=YYYY-MM-DD` |
| BMS по модулях (5 хв) | `GET /api/residential/history/data/bms/list?deviceId=…&stime=YYYY-MM-DD` |
| Активні аварії | `POST /api/web/fault/list/real` `{current, size}` |
| Історія тривог з `removeTime` | `POST /api/web/residential/station/detail/history/fault` `{stationId, pageNumber, pageSize}` (до 200 на сторінку, фільтр дат ігнорується) |
| Оновлення прошивки | `GET /api/web/station/detail/need/upgarde/V2?stationId=…` |
| Читання параметра інвертора | `POST /api/residential/kse/remote/readvalue` `{deviceId, setItem, command, coefficient, registerCount}` → `GET …/readvalue/result?commandId=…` |
| Швидке оновлення | `GET /api/residential/device/detail/start/refresh?collectId=…` / `stop/refresh`, далі `logic?refreshFlag=true` |

Усі запити йдуть із заголовком `Authorization: Bearer <token>` із сесії порталу.

## Налаштування

На початку скрипта в `dash.html`: запасна ємність батареї (`BATT_KWH`, лише коли BMS не повідомляє ємність модулів), запасна межа розряду (`MIN_SOC`), інтервал оновлення і умовний ресурс циклів.

## Застереження

Це незалежний проєкт, не пов'язаний з KSTAR і не схвалений нею. Він використовує той самий API, що й веб-інтерфейс порталу, і лише читає дані; єдині команди, які він надсилає, це старт/стоп Quick Update і читання параметрів.
